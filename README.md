# Abissal

A daily trivia game in Portuguese where the obvious answer loses. Seven prompts a day, 25 seconds each: any correct answer counts, but the fewer players who think of it, the deeper your lure sinks.

**Stack:** static site on GitHub Pages · Supabase (Postgres + Row Level Security + anonymous auth + an Edge Function) · Gemini API (free tier) to judge answers that are not on the built-in lists.

```
site/ (GitHub Pages)  ──►  Supabase Postgres      answer counts, daily scores, leaderboard
                      ──►  Edge Function "judge"  ──►  Gemini API   (only for unlisted answers)
```

| Path | What it is |
|---|---|
| `site/index.html` | The game |
| `site/admin.html` | Your review page for answers the judge accepted or rejected |
| `site/prompts.json` | 143 prompts and their known answers, generated by `gen/` |
| `site/config.js` | Your Supabase URL and public key (step 4) |
| `supabase/migrations/…_init.sql` | Tables, security rules and the functions the site calls |
| `supabase/functions/judge/index.ts` | The judge: checks an answer with Gemini, caches the decision, enforces a daily limit |
| `gen/` | Python lists and generator for `prompts.json` |
| `.github/workflows/pages.yml` | Publishes `site/` to GitHub Pages on every push to `main` |

## Setup (about 30 minutes)

### 1. Put the code on GitHub
Create a new repository (for example `abissal`), then from this folder:
```bash
git init && git add . && git commit -m "Abissal"
git branch -M main
git remote add origin https://github.com/YOUR-USER/abissal.git
git push -u origin main
```
In the repo: **Settings → Pages → Build and deployment → Source: GitHub Actions**. The workflow publishes the site at `https://YOUR-USER.github.io/abissal/`. It will run in offline mode until step 4.

### 2. Create the Supabase project
At [supabase.com](https://supabase.com), create a free project. Pick the **South America (São Paulo)** region.

### 3. Create the database
**SQL Editor → New query**, paste all of `supabase/migrations/20261122000000_init.sql`, and click **Run**.

Then **Authentication → Sign In / Providers**, and turn on **Allow anonymous sign-ins**. Players never create an account: each browser gets an anonymous user.

### 4. Connect the site
In Supabase, open **Connect** (or **Project Settings → API Keys**) and copy the **Project URL** and the **publishable / anon** key. Put them in `site/config.js`, then commit and push.

That key is meant to be public. The database rules only let each player read and write their own rows. Never put the `service_role` / secret key in the site.

At this point the game works with the leaderboard and live rarity, but only answers on the lists are accepted.

### 5. Get a Gemini API key (free)
At [aistudio.google.com](https://aistudio.google.com), sign in with a Google account and click **Get API key → Create API key**. No card is needed for the free tier.
Check your free limits at [aistudio.google.com/rate-limit](https://aistudio.google.com/rate-limit). On the free tier Google may use the requests to improve its products; here that is only the prompt and the typed answer.

### 6. Deploy the judge
In Supabase, **Edge Functions → Secrets**: add `GEMINI_API_KEY` with your key.

The function itself (`supabase/functions/judge`) can be deployed from the dashboard or with the CLI:
```bash
npx supabase login
npx supabase link --project-ref YOUR-PROJECT-REF
npx supabase functions deploy judge --no-verify-jwt
```
`--no-verify-jwt` is safe here: the function checks the player's login itself.

Optional secrets:
- `GEMINI_MODEL`: defaults to `gemini-3.5-flash-lite`. Check current model names at [ai.google.dev/gemini-api/docs/models](https://ai.google.dev/gemini-api/docs/models).
- `JUDGE_DAILY_LIMIT`: defaults to `40`.
- `PROMPTS_URL`: defaults to `https://joaosnts22.github.io/Abissal/prompts.json`.

Test it by typing an answer that is not on any list, like `jambo-rosa` for "Uma fruta".

### 7. Make yourself the admin
1. In **Authentication → URL Configuration**, set **Site URL** to your Pages URL. Add `https://YOUR-USER.github.io/abissal/admin.html` to **Redirect URLs**.
2. Open `/admin.html`, enter your email, and click the link you receive.
3. The page shows a SQL line with your user id. Run it in the SQL Editor and reload.

The review page has four tabs: **Juiz aceitou**, **Juiz recusou**, **Approved** and **Rejected**. Your decision overrides the judge's for every future player. You can also fix the saved name before approving.

## How rarity works
Every built-in answer has an obscurity rating from 1 (obvious) to 7 (extremely obscure), stored in `gen/ratings.json` and baked into `site/prompts.json` (`Name/alias#rating`).

| Rating | Tier | Points |
|---|---|---|
| 1 | Sardinha | 10 |
| 2 | Baiacu | 25 |
| 3 | Polvo | 45 |
| 4 | Arraia | 65 |
| 5 | Lula-gigante | 85 |
| 6 | Peixe-abissal | 100 |
| 7 | Um em um milhão | 150 |

- **Um em um milhão:** at most 2 predefined answers per prompt, its two most obscure (rated 6 or 7), plus any off-list answer the judge rates 7.
- **Off-list answers:** the judge also rates them, so a common answer that was missing from the list doesn't become abissal.
- **Players only make it harder:** once a prompt has 10+ answers, an answer many players give is capped at a lower tier, and a one-in-a-million answer given by 2+ players drops to Peixe-abissal.
- **Depth:** 10 m per point; a perfect day (7 × 150) reaches 10,500 m.

**Re-rating after editing the lists:** deploy `supabase/functions/rate`, then in the SQL Editor insert a token into `rating_jobs` and call the function once with `net.http_post` (body `{"token": "...", "i": 0}`). It works through every list in batches of 100, paced for the Gemini free tier, and writes to `public.ratings`. Export the ratings into `gen/ratings.json` and run `python gen/gen.py`.

## Maintenance
- **Add answers or prompts:** edit the lists in `gen/data_*.py` and run `python gen/gen.py`. That rewrites `site/prompts.json`; then push. In a list, `/` separates aliases (`Mexerica/Tangerina`) and a trailing `?` drops an entry.
- **Move reviewed answers into the lists:** use **Copiar aprovadas (JSON)** on the review page, then add the names to `gen/`.
- **Daily questions:** they come from a seed based on the date, so everyone gets the same 7. They change at midnight, Brasília time.

## Known limits
- **Scores are calculated in the browser.** Someone who knows how could send a fake score to the leaderboard. That's fine for a game among friends; the fix is to move scoring into a Postgres function.
- **Anonymous players are tied to their browser.** Clearing site data or switching devices starts a new player.
- **Abuse protection:** Supabase recommends turning on CAPTCHA (Turnstile) for anonymous sign-ins before sharing the site widely.

## Data you can analyze
```sql
-- most common answers per prompt
select prompt_id, answer_name, count(*) from answers group by 1,2 order by 1,3 desc;
-- how rare the average player is
select day, avg(score), count(*) from dives where done group by day order by day;
```
